# FairCheck-CI Gate Documentation

This document describes the Continuous Integration (CI) component of **FairCheck-CI**, an SMT-based fairness regression testing framework for AI decision pipelines.

The CI gate consumes formal verification results produced by the SMT verification layer and translates them into software-engineering-oriented PASS, FAIL, or WARNING decisions that can be integrated into automated development workflows.

---

# 1. Purpose

FairCheck-CI extends fairness assessment beyond metric reporting by treating fairness verification as a regression-testing activity.

The CI gate provides an automated mechanism for:

* evaluating fairness verification outcomes,
* detecting newly introduced fairness violations,
* generating developer-facing diagnostic evidence,
* supporting model promotion decisions within a CI workflow.

The goal is to enable fairness checks to become part of a repeatable software engineering process rather than a one-time evaluation activity.

# 4. Decision Policy

FairCheck-CI maps SMT verification outcomes into CI decisions.

| SMT Result             | CI Decision |
| ---------------------- | ----------- |
| UNSAT                  | PASS        |
| SAT                    | FAIL        |
| TIMEOUT / Inconclusive | WARNING     |

Interpretation:

* **PASS (UNSAT)** indicates that no fairness counterexample was found within the encoded verification setting.
* **FAIL (SAT)** indicates that at least one fairness counterexample was detected.
* **WARNING** indicates that verification could not be completed within the configured resource limits.

These decisions are scoped to the encoded model, selected sensitive attribute, fairness property, and verification assumptions used in the experiment.

---

# 5. Exit Codes

The CI gate returns process exit codes that can be consumed by automated workflows.

| Exit Code | Meaning |
| --------- | ------- |
| 0         | PASS    |
| 1         | FAIL    |
| 2         | WARNING |

Example:

```text
PASS     -> Exit Code 0
FAIL     -> Exit Code 1
WARNING  -> Exit Code 2
```

This allows CI systems to automatically block, warn, or approve model promotion.

---

# 6. Fairness Property Being Verified

The current implementation evaluates a causal-style individual fairness property.

Informally, the property checks whether:

> Two instances that are identical on all non-sensitive features but differ only in a selected sensitive attribute should receive the same prediction.

The SMT solver searches for counterexamples violating this property.

If such a counterexample exists, the solver returns SAT and the CI gate reports FAIL.

If no counterexample is found within the encoded verification domain, the solver returns UNSAT and the CI gate reports PASS.

# 8. Running the CI Gate

Execute the CI gate after generating the formal verification results.

```bash
python ci/ci_gate_runner.py
```

The script reads the processed verification artifacts and generates the CI reports.
